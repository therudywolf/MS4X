# 03. Что в образе, и патчлисты сообщества

[`tools/ms4x_core.py`](../../tools/ms4x_core.py) `info` читает образ MS42 0110C6 или MS43 430069 до того, как в него что-то пишут. Сам он ничего не меняет.

```
python3 tools/ms4x_core.py info ОБРАЗ [--patchlist ПАТЧЛИСТ.xdf ...] [--stock ЗАВОДСКОЙ.bin] [--json]
```

## Что он показывает

Заводская MS43 430069:

```
program        Siemens MS43 430069, 524288 bytes
labels         program 432900104300696577355117--11143053690111143053, calibration C769Y548
program part   stock (SHA-256 of the program checksum blocks bb63da0e7ee2baf2...)
checksum       0x73FE0 stored 0xD37E, the program's own routine gives 0xD37E
checksum       0x6FDE0 stored 0x727E, the program's own routine gives 0x727E
sum32          0x6FDAE stored 0xB3DAAD17, the seed plus the words of 0x50000-0x53BF7, 0x6E876-0x6E877 gives 0xB3DAAD17
sum32          0x72FFC stored 0xA61EB8D5, the seed plus the words of 0x712C6-0x71315, 0x7EB94-0x7EE15 gives 0xA61EB8D5
free area      0x4A8CC-0x4FFFF: empty
```

- **Программа и метки.** Программа по её метке, метка программной части (MS42 0x5002E, MS43 0x6FFB2) и первые символы калибровки (MS42 0x48000, MS43 0x70000).
- **Программная часть.** SHA-256 по блокам программной суммы — тем байтам, которые блок проверяет сам. Он одинаков у всех 16 заводских образов 0110C6 и у всех 18 образов 430069 из ms4x-net, поэтому «stock» здесь значит: в проверяемой программе не изменён ни один байт.
- **Контрольные суммы.** Обе суммы, посчитанные собственной подпрограммой CRC программы в эмуляторе (документ 02), рядом с записанными. Сумму, которая не сходится, перед прошивкой надо исправить (большинство флешеров делают это сами).
- **Две 32-битные суммы 430069.** Кроме CRC-16 MS43 держит две аддитивные суммы (см. «Находки» ниже): одну по программе, записана в 0x6FDAE, одну по двум кускам калибровки, записана в 0x72FFC. `info` считает обе по дескрипторам из самого образа и показывает рядом с записанными. Пересчитывает ли их ваш флешер, стоит проверить здесь: блок — пересчитывает, в фоне.
- **Свободная область.** Часть программы, которую заводской код оставляет пустой и куда патчи кладут свой код: MS42 0x60C44-0x6FFFF, MS43 0x4A8CC-0x4FFFF, обе вне программной суммы. Каждый занятый кусок назван тем патчем, чьи байты там лежат.
- **`--patchlist`.** Каждый патч патчлиста TunerPro (записи `XDFPATCH`) показывается так:

| Состояние | Что значит |
|---|---|
| applied | в каждой записи байты, которые пишет патч |
| not applied | в каждой записи её исходные данные |
| not applied, expects another patch first | запись ещё пустая (0xFF), а её исходные данные — это байты другого патча |
| partly applied | в части записей патч, в остальных исходные данные |
| changed otherwise | в записи ни то, ни другое: там другой патч или другой код |

  Патч, который возвращает заводские байты (например, снимающий более старый патч), на заводском образе показывается как applied. Патчи списка, которые делят байты, тоже перечисляются.
- **`--stock`.** Куски с 0x10000 и выше, без калибровки, где образ отличается от заводского образа той же программы, с записью патча, чьи байты там лежат, или с пометкой, что это записанная сумма.

Байты патчей берутся из того патчлиста, который вы даёте; копии патчлистов в этом репозитории нет.

## «Заводской» дамп может быть не заводским

Дамп, считанный с машины и хранимый как исходный, может уже нести патчи. С патчлистом и заводским образом `info` показывает, какие именно, по записям, и что осталось сверх них. Проверяйте программную часть, прежде чем что-то строить на дампе.

## Патчи, которые делят байты

В патчлистах сообщества MS42 v1.7.1 и MS43 v2.9.2 байты делят такие пары:

| Программа | Патчи | Общие байты |
|---|---|---|
| 0110C6 | Custom CAN - OLM Boost Gauge и M Cluster LED Support | 0x60D4A-0x60D53: первый ждёт, что второй уже стоит |
| 0110C6 | M3 и M5 Cluster LED Mod Default Values | данные 0x4F860-0x4F87D: одно или другое |
| 430069 | Remove Deprecated Launch Control и Launch Control & Rolling Anti Lag | 0x58C14-0x58C83 |
| 430069 | Remove Deprecated Launch Control и DS2 Logging Feature Enhancement | 0x4AACA-0x4AAF5 |
| 430069 | Remove Deprecated Launch Control и LC & RAL Default Values | данные 0x71316-0x7131A |
| 430069 | MAF Sensor Hack 2048kg/h и 4096kg/h | 0x3B4C3, 0x3B4E7: одно или другое |

## Находки в заводских программах

Факты, найденные по дороге, которые стоит знать каждому, кто правит эти образы; ни один не про какой-либо слой.

- **430069 держит две 32-битные суммы кроме CRC-16.** Фоновая задача (код 0x5FBE0–0x5FD58, подпрограмма суммирования 0x5FD7C) складывает 16-битные слова двух диапазонов к затравке, по два прохода на сумму, и сравнивает результат с записанным словом. Дескрипторы лежат в образе в 0x6FDAE–0x6FDDD: записанная сумма программы (0x6FDAE), затравки (0x6FDB2, 0x6FDB8, обе 0xA5A5A5A5), затем по две пары дальних указателей [начало, конец) на сумму: сумма программы по 0x50000–0x53BF7 и 0x6E876–0x6E877, сумма калибровки по 0x712C6–0x71315 и 0x7EB94–0x7EE15, записана в 0x72FFC. Расхождение ставит бит 0xFD7E.8 и регистрирует ошибку 8 (`calls 0x0E:0x1192`); для суммы калибровки байт 0x70E07 = 0xA5 обходит проверку (сток: 1); этот байт — запись `lc_swi_cal_mon_cks` патча сообщества Checksum Bypass, остальные три записи которого обходят проверки CRC-16. Все 18 заводских образов ms4x-net сходятся по обеим суммам; `info` их показывает.
- **RAM MS43, которая выглядит свободной, не свободна.** Цикл инициализации 0x33300 при каждом включении заполняет 0x8976–0x8A75 и 0x8AE4–0x8BE3 (по 256 копий байт из 0x8970 и 0x8ADE). Кто ищет свободную RAM под свои ячейки, должен сканировать весь код на писателей, а не на читателей ячейки.
- **Один заводской образ не сходится сам с собой.** В `Siemens_MS43_MS430069_E39_M54B25_EU4_LHD.bin` из ms4x-net записана калибровочная CRC, которую его содержимое не даёт (документ 02).
