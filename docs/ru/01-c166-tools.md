# 01. Инструменты C166: дизассемблер, ассемблер, обход кода

[`tools/c166.py`](../../tools/c166.py) читает и пишет код C167 в Siemens MS42 (программа 0110C6) и MS43 (программа 430069). Одна таблица форм команд работает в обе стороны: что дизассемблер напечатал, то ассемблер превращает обратно в те же байты. Python 3, других пакетов не нужно.

## Команды

| Команда | Что делает |
|---|---|
| `python3 tools/c166.py dis ОБРАЗ НАЧАЛО [КОНЕЦ]` | Листинг: смещение в файле, байты, команда, комментарий |
| `python3 tools/c166.py func ОБРАЗ АДРЕС` | Одна функция по её ходу, с метками; в вызовы не заходит |
| `python3 tools/c166.py funcs ОБРАЗ` | Функции, достижимые от векторов и дальних вызовов, с числом вызывающих |
| `python3 tools/c166.py xref ОБРАЗ АДРЕС [НАЧАЛО КОНЕЦ]` | Команды, которые вызывают `АДРЕС` или прыгают на него, обращаются к нему как к данным, регистру или биту, грузят его как 16-битную константу |
| `python3 tools/c166.py asm ИСХОДНИК -o ВЫХОД [--org АДРЕС]` | Собирает исходник в синтаксисе листинга в плоский файл |
| `python3 tools/c166.py check ОБРАЗ [НАЧАЛО КОНЕЦ]` | Разбирает и собирает обратно; называет каждую команду, которая не дала тех же байт |

`--profile ms42 | ms43 | raw` выбирает карту памяти; по умолчанию она берётся по метке программы в образе (`0110C6` в 0x48008, `430069` в 0x6FFBA). `--dpp P0,P1,P2,P3` задаёт другие значения DPP.

## Синтаксис

| Операнд | Как пишется | Пример |
|---|---|---|
| Регистр слова и байта | `r0`-`r15`, `rl0`-`rh7` | `mov r4, r5` |
| Регистр специальных функций | имя из таблицы регистров руководства C167CR (`PSW`, `DPP0`, `T2`, `ADCON`, после EXTR `DP0L`, `XP0IC`...) или адрес слова | `mov T2, #0x0000`, `mov 0xFE40, #0x0000` |
| Прямая память | `[адрес]` | `movb rl4, [0x8100]` |
| Косвенная | `[r4]`, `[r4+]`, `[-r0]`, `[r4+#0x0010]` | `mov r4, [r5+#0x0010]` |
| Константа | `#5` десятичная: форма на 3 или 4 бита; `#0x05`: 8 бит; `#0x0005`: 16 бит | `mov r4, #5` это `E0 54`, `mov r4, #0x0005` это `E6 F4 05 00` |
| Бит | `слово.бит`: `PSW.3`, `r4.3`, `0xFD10.3` | `jb PSW.3, 0x49D10` |
| Условие | `cc_UC`, `cc_EQ`, `cc_NE`, `cc_ULT`, `cc_UGE` и остальные; принимаются и `cc_Z`, `cc_NZ`, `cc_C`, `cc_NC` | `jmpr cc_NE, 0x49D02` |
| Адрес перехода | смещение цели в файле | `calla cc_UC, 0x4A000` |
| Дальний адрес | `сегмент:смещение` | `calls 0x0C:0x9CF8` |

Запись константы выбирает кодировку, поэтому листинг собирается обратно точно. В исходнике можно писать метки (`имя:`), `org АДРЕС`, `db` и `dw`, а также строки, скопированные из листинга (адрес и байты в начале читаются, дальше текст).

## Что показывает листинг

Из заводской MS43 430069:

```
1DCC2  DA 0C 38 5B  calls 0x0C:0x5B38                 ; file 0x45B38
1DCE4  F3 F8 89 80  movb rl4, [0x8089]                ; ext RAM 0x40089
1DCE8  D7 40 10 00  extp #0x010, #1                   ; next 1
1DCEC  F7 F8 E8 1C  movb [0x1CE8], rl4                ; ext RAM 0x41CE8
```

- Адрес — смещение в файле, как в шестнадцатеричном редакторе и в XDF.
- Адрес данных показан физически, через DPP профиля или через страницу или сегмент предшествующего `EXTP` / `EXTS`, и что там лежит: смещение в флеше, внешняя RAM, XRAM (0xE000-0xE7FF), IRAM (0xF600-0xFDFF), регистр по имени или часть модуля CAN: `CAN object 1 data 0` — это 0xEF17, байт 0 объекта сообщения 1.
- После `EXTR`, `EXTPR` и `EXTSR` регистры и биты следующих команд — расширенные SFR (0xF000-0xF1FF), и печатаются эти адреса.
- У дальнего вызова показано смещение цели в файле.
- Байты, которые не команда, печатаются как `db`. Если у известной команды не нулевое зарезервированное поле, это сказано в комментарии.

## Карты памяти

| | MS42 0110C6 | MS43 430069 |
|---|---|---|
| Флеш в файле | смещение в файле = физический адрес | флеш виден с 0x00000 и с 0x80000: смещение в файле = физический адрес & 0x7FFFF |
| Код | сегменты 0-7 (например, 0x61234 это `06:1234`) | сегмент 0 (запуск) и сегменты 9-0x0F: `calls 0x0C:0x9CF8` ведёт в файл 0x49CF8 |
| DPP0, DPP1, DPP2, DPP3 после запуска | 0x12 (0x48000), 0x14 (0x50000), 0x13 (0x4C000), 0x03 | 0x1C (0x70000, калибровка), 0x3B (0xEC000 = файл 0x6C000), 0x10 (внешняя RAM 0x40000-0x43FFF), 0x03 |
| Калибровка | 0x48000-0x4FFFF | 0x70000-0x7FFFF |

DPP3 = 3 — системная страница C167: XRAM, модуль CAN, IRAM и SFR. Листинг считает по значениям DPP после запуска; функцию, которая грузит другие значения (в MS43 некоторые функции таблиц меняют DPP0), он читает по значениям запуска, такие места проверяйте руками.

## Как проверено

`python3 tests/test_c166.py`; GitHub Actions запускает его в каждом pull request вместе с заводскими образами.

- Каждый первый байт с каждым вторым и несколькими продолжениями, в обоих состояниях EXTR (больше 600 000 случаев), разбирается в текст, который собирается обратно в те же байты. 236 первых байтов — команды; 20 у C167 не используются: 0x3B, 0x44, 0x45, 0x83, 0x85, 0x8B, 0x8C, 0x93, 0x95, 0xA3, 0xB3, 0xC1, 0xC3, 0xC7, 0xD3, 0xE3, 0xE5, 0xF5, 0xF8, 0xF9.
- Больше сотни кодировок, одна или несколько на каждую раскладку из руководства Infineon *Instruction Set Manual for the C166 Family* V2.0 (2001), в обе стороны; каждая раскладка инструмента сверена с этим руководством. Имена регистров взяты из таблицы 22-4 руководства *C167CR Derivatives User's Manual* V3.1 (2000).
- 16 заводских образов 0110C6 и 18 образов 430069 из репозиториев [ms4x-net](https://github.com/ms4x-net), перечислены с SHA-256 в [`tests/ms4x_images.txt`](../../tests/ms4x_images.txt) и скачиваются для прогона, здесь не хранятся. Каждый их байт разбирается и собирается обратно. Код, достижимый от векторов и дальних вызовов (MS42: 471 функция, около 66 000 команд; MS43: 650 функций, около 73 000 команд), разбирается без пропусков.
- Байты `BFLDL` и `BFLDH` устроены по-разному: `0A QQ маска данные` и `1A QQ данные маска`, синтаксис у обеих `bitoff, #маска, #данные`. Если читать так, байт данных лежит внутри маски в каждой `BFLDL` и `BFLDH` заводского кода.
- В заводском коде байтовая команда с 8-битной константой хранит в неиспользуемом байте знаковое расширение: `CMPB RL0, #-9` записано как `47 F0 F7 FF`. Процессор читает только младший байт; инструмент показывает `#0xFFF7` и сохраняет записанный байт.

## Ограничения

- Адрес данных у `[r4]` и других косвенных операндов без выполнения кода не известен.
- `xref` — линейный проход: таблицы между функциями тоже разбираются как команды, поэтому каждое попадание проверяйте в его функции.
- Обход идёт по прямым переходам и вызовам; задачи, которые вызываются через таблицы указателей, находятся по дальним вызовам линейного прохода, и цель засчитывается, только если её собственный ход не упирается в пропуск.
- Эмулятор — следующий шаг.
